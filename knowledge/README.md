# מאגר הידע של countme (knowledge vault)

מאגר זה הוא ה"מוח" הטקסטואלי שממנו שקל (סוכן הצ'אט) שולף הסברים מדויקים, מנוסחים היטב ובעברית תקנית — במקום להמציא ניסוח בזמן אמת. הוא נבנה ותוחזק כ-vault תואם Obsidian, בדיוק כמו `memory/` שכבר קיים בפרויקט, אבל עבור ידע מקצועי-רגולטורי במקום סטטוס פרויקט.

## מה יש כאן

7 תיקיות דומיין, כל אחת עם קבוצת פתקים (notes) ממוקדים:

| תיקייה | נושא |
|---|---|
| `מס-הכנסה/` | טופס 1301, מקדמות, נקודות זיכוי, מדרגות מס, פנסיה, טפסים נלווים |
| `מעמ/` | דוח מע"מ, מס עסקאות/תשומות, תדירות דיווח, יצוא ואפס-אחוז |
| `ביטוח-לאומי/` | ביטוח לאומי לעצמאי, מדרגות תשלום, ניכוי, מקדמות |
| `מסמכים-וחשבוניות/` | חשבונית מס, קבלה, מספר הקצאה, שמירת מסמכים, תיעוד |
| `הוצאות-מוכרות/` | כללי ניכוי הוצאות: רכב, טלפון, כיבוד, ביגוד, פחת, נסיעות |
| `עוסק-פטור-זעיר-מורשה/` | הבדלי המעמדות, תקרת מחזור, תהליך המעבר למורשה |
| `פרטיות-ורגולציה/` | תיקון 13, רישום מאגר מידע, זכויות נושא מידע, אבטחת מידע |

כל פתק הוא קובץ Markdown בודד עם front-matter (מטא-דאטה) ו-body קצר (כ-200–600 מילים) שנכתב **לציטוט ישיר** — שקל אמור להיות מסוגל להעתיק ממנו משפטים כמעט כפי שהם כשהוא עונה למשתמש.

## חוזה ה-vault

### 1. תואם Obsidian, ניתן לעריכה אנושית
כל קובץ הוא Markdown רגיל עם YAML front-matter. אפשר לפתוח את התיקייה כ-vault ב-Obsidian, לערוך, להוסיף פתקים, לגרור קישורים — בלי כלים מיוחדים. front-matter סטנדרטי לכל פתק:

```yaml
---
title: "שם הפתק"
topic: מס-הכנסה          # שם התיקייה/דומיין
tags: [תגית-1, תגית-2]
related_fields: ["150", "030"]   # קודי שדות טופס 1301 רלוונטיים, אם יש
year_sensitive: true      # true אם התוכן תלוי בערכי שנת מס שמתעדכנים
source: ["israeli-tax-returns"]  # סקילס/מסמכים שמהם נשאב התוכן
---
```

### 2. wikilinks = גרף היחסים
קישורים בין פתקים כתובים כ-`[[שם-הקובץ]]` (בלי סיומת `.md`). זה התחליף למאגר וקטורי: הגרף שנוצר מהקישורים ההדדיים *הוא* מבנה הידע. פתק על "מקדמות מס הכנסה" מקשר ל"טופס 1301" ול"מדרגות מס"; פתק על "עוסק זעיר" מקשר ל"עוסק פטור" ול"עוסק מורשה" וכן הלאה. ככל שהגרף עשיר יותר, כך קל יותר לאינדקסר ולסוכן לדעת אילו פתקים "קרובים" לשאלה נתונה גם כשאין התאמת מילות-מפתח מדויקת.

### 3. איך זה מוזן למערכת (בהתאם לארכיטקטורה שאושרה 18/08)
המאגר הזה הוא המקור (source of truth) הטקסטואלי. בזמן deploy, אינדקסר טוען את כל הפתקים ל-Postgres (טבלה עם `pg_trgm` + חיפוש טקסט מלא `simple`, שתי יכולות חינמיות שתומכות היטב בעברית). **אין embeddings ואין קריאות ל-API חיצוני** — כל הזרימה קלוד-בלבד:

1. **טבלת תוכן (TOC) קומפקטית** — רשימת כותרות+תגיות של כל הפתקים, נטענת ל-system prompt של שקל עם prompt caching (בלוק סטטי, זול לשמור בקאש).
2. **כלי חיפוש (`search_knowledge`)** — שאילתת SQL היברידית אחת מעל `pg_trgm`+FTS, מחזירה את הפתקים הרלוונטיים ביותר לשאילתת המשתמש.
3. **כלי קריאה (`read_chunks`)** — טוען את גוף הפתקים שהחיפוש החזיר, כדי ששקל יוכל לצטט מהם ישירות.

התהליך אינו RAG וקטורי קלאסי — אין שכבת embedding, אין vector DB. זו החלטה מכוונת: אפס ספקים חדשים בתשלום, הכול Claude-native וכל תשתיות Postgres שכבר קיימות ב-Supabase.

### 4. כלל הזהב: אין מספרים בפתקים
**שום פתק לא מכיל תקרה, אחוז, סכום בש"ח, מדרגת מס או תאריך יעד קונקרטיים.** הסיבה: כל הערכים האלה מתעדכנים (לפעמים כמה פעמים בשנה), ומקור האמת היחיד עבורם הוא השכבה המחושבת בקוד — `lib/calculators/types.ts` (`getTaxYearConstants`) וה-tools שדרכם שקל קורא אותם בזמן אמת. אם פתק היה "מקפיא" מספר בטקסט, הוא היה הופך לשקר תוך חודשים.

**מה כן מותר:** לקרוא לתקרה/לאחוז/למדרגה **בשם שלה** — "תקרת עוסק פטור", "שיעור המע\"מ הרגיל", "מדרגת המס העליונה" — ולהפנות לשדה הטופס או לכלי המחשוב הרלוונטי. לדוגמה: *"התקרה המעודכנת זמינה דרך המערכת (ראו שדה 238)"* במקום *"התקרה היא 122,833 ₪"*.

התוצאה: כשמשתמש שואל "כמה זה תקרת הפטור?", שקל לא עונה מהפתק — הוא קורא ל-tool שמחשב את הערך המדויק לשנת המס הרלוונטית, ומשתמש בפתק רק כדי להסביר את **המשמעות וההקשר** של המספר שהתקבל.

### 5. עקרונות תוכן נוספים
- **כל טענה מבוססת מקור.** ה-`source` ב-front-matter מצביע לסקילס/מסמך שממנו נשאבה הקביעה. שום פתק לא מכיל "אמת" שלא נבדקה מול מקור — אם משהו לא היה מבוסס מספיק, הוא לא נכתב כפתק בכלל (ראו "flags" בדוח המסירה של סבב היצירה הזה).
- **רישום פשוט, לא ייעוץ.** פתקים רגישים (כאלה שיכולים להישמע כהמלצת פעולה אישית) מסתיימים בשורת ההבהרה הסטנדרטית: *"countme הוא מחשבון מדויק לפי הנתונים שהזנתם — לא ייעוץ מס אישי. למקרים מורכבים, פנו לרואה חשבון או יועץ מס."*
- **טון:** עובדתי, חם, בלי שפת "מומלץ לך/כדאי לך" — ראו את ההבחנה בין "ההוצאה מסווגת כ..." (כלי) לבין "מומלץ לך לדרוש את ההוצאה" (ייעוץ) שמופיעה גם במפת הרגולציה של countme עצמה.

## איך מוסיפים פתק חדש

1. בחרו תיקיית דומיין מתאימה (או הציעו דומיין חדש אם אף אחת לא מתאימה).
2. קובץ Markdown חדש עם front-matter מלא (title/topic/tags/related_fields/year_sensitive/source).
3. גוף קצר וממוקד (200–600 מילים), כתוב לציטוט ישיר.
4. `[[wikilinks]]` לפתקים קשורים קיימים — וגם עדכנו את הפתקים הקיימים להצביע חזרה, אם רלוונטי.
5. בלי מספרים קונקרטיים של תקרות/שיעורים/מדרגות/תאריכי-יעד — רק שמות המושגים + הפניה לשדה/לכלי.
6. אם אתם לא בטוחים שהתוכן מבוסס-סקיל — אל תכתבו אותו כפתק. תעדו את זה כפריט פתוח במקום אחר (למשל ב-`memory/decisions.md` תחת "שאלות פתוחות") עד שמישהו יאמת מול המקור.
