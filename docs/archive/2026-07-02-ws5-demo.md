# WS5 — Regulatory-Watch hardening: end-to-end demo record (2026-07-02)

Hardening of the daily regulatory-watch pipeline: a **cross-reference stage** (corroboration + provenance on every item) and a **params-patch proposal stage** (ready-to-review unified diff attached to the GitHub issue, never auto-applied). This document records what was built and an actual end-to-end run in this container.

## What changed (files)

| File | Change |
|---|---|
| `scripts/regulatory-watch/cross-ref.ts` | **NEW.** Corroboration: primary-source (`taxes-gov`, `gov-il-rss`) OR ≥2 distinct sources with matching normalized Hebrew titles (prefix-tolerant Jaccard ≥ 0.4, ≥2 shared tokens; final-letter folding, niqqud/punctuation stripping, stopwords). Attaches `Provenance` (source id + label + publish date + fetch date) to every item. Pure, no deps, never throws. CLI self-test built in. |
| `scripts/regulatory-watch/propose-patch.ts` | **NEW.** For each classified `affectedConstants[]` entry with a concrete numeric `proposedValue`: builds a unified diff against `src/lib/calculators/types.ts` — the `TAX_YEAR_2024` scalar **plus** the `TAX_CONSTANT_META` provenance entry (`sourceUrl` → the publication, `lastVerified` → run date). Proposed text is validated against the `edge-cases.ts` invariants before being offered. Renders the issue-body section with a "human must review, never auto-merged" banner. Degrades to no-op without classification. CLI simulation mode built in. |
| `scripts/regulatory-watch/run.ts` | Wired both stages: fetch → **cross-ref (whole fetch, so seen items still corroborate new ones)** → dedup → classify → **patch proposal** → issues. Corroborated findings open issues first; single-source findings get title tag `[מקור יחיד]` + `single-source` label. Explicit `env-blocked: ANTHROPIC_API_KEY` detection (logged, and stamped into the summary `classifyStatus` + per-item skip reasons). Summary now carries `sourceCounts` (per-source item count + fetch date) and per-finding `provenance` + `corroboration`. |
| `scripts/regulatory-watch/issues.ts` | `buildIssueBody(item, cls, extras?)` — adds provenance header (source label + fetched-at), a cross-reference section (verdict + matched publications with dates), and the patch-proposal ```` ```diff ```` section. |
| `scripts/regulatory-watch/report.ts` | `Finding` gains optional `provenance` / `corroboration`; `RunSummary` gains optional `classifyStatus` / `sourceCounts` (all backward compatible — `report.smoke.ts` still passes 11/11). PDF report renders the corroboration verdict + fetch date per finding. |
| `.github/workflows/regulatory-watch.yml` | Comment-only update: new stages run inside `run.ts`; **no new steps, no new permissions** (`issues: write` only); patch proposals live in the issue body, nothing is auto-PRed. |

## Known gaps / follow-ups

- The `@@` hunk line numbers in a proposal go stale if `types.ts` changes between the daily run and human review — the reviewer applies via `apply.ts` (name+value, position-independent) in that case; the diff is primarily for *reading* the change.
- Diff targets the first scalar occurrence — i.e. `TAX_YEAR_2024` (same "keys are unique per year-block, 2024 declared first" contract `apply.ts` already relies on). Multi-year updates (e.g. a 2026-only change) still need a human editing the right year block.
- Similarity matching is title-token based; two sources describing the same change with fully disjoint vocabulary won't corroborate (item stays single-source — reported, just demoted). Acceptable by design: false-negative corroboration only lowers priority, never drops an item.
- `shituf` + `knesset` returned 0 even via fixtures because their real URLs were intentionally left un-overridden — CI should watch the `⚠ … 0 items` warnings for genuinely dead endpoints.
